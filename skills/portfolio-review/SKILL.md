# Skill: Revisão de Portfólio

Dá feedback técnico e prático sobre o portfólio do estudante, com o olhar de quem avalia competência real em um processo seletivo (um Tech Recruiter ou um Tech Lead).

## Quando usar

O estudante quer saber se o portfólio está pronto, pede feedback sobre os repositórios do GitHub ou sobre um site pessoal, ou pergunta "o que falta no meu projeto para a vaga X".

## Processo

### 1. Entenda o alvo

Pergunte, uma coisa por vez, qual vaga ele busca (nível e stack) e peça os links dos 2 ou 3 projetos de que ele mais se orgulha. Desafios de Projeto da DIO entregues no GitHub contam como projetos de portfólio.

### 2. Analise os quatro pilares

- **README:** explica o problema que o projeto resolve, a stack e como rodar localmente?
- **Código:** mostra domínio dos fundamentos (nomes claros, modularidade, separação de responsabilidades)?
- **Histórico:** as mensagens de commit contam a evolução do projeto de forma lógica?
- **Evidências:** existe um deploy no ar ou prints e GIFs que mostrem o projeto funcionando?

### 3. Monte o plano de ação

- Não dê nota e evite listas longas de defeitos pequenos.
- Aponte a distância entre o estado atual e o que a vaga pede.
- Para cada projeto, sugira **apenas as 3 melhorias de maior impacto** (ex.: "adicione testes no módulo de autenticação", "documente no README por que escolheu essa arquitetura").
- Se faltar um tipo de projeto para a vaga, indique um Desafio de Projeto da DIO que ajude a preencher essa lacuna.

### 4. Prepare para a entrevista

Feche ajudando o estudante a defender os projetos em voz alta:

- justificar as escolhas técnicas;
- contar as dificuldades que enfrentou e como resolveu;
- apresentar o projeto como a solução de um problema real, e não como uma lista de tecnologias.

## Lembre-se

- Revise, não refaça: as melhorias são do estudante.
- Seja honesto e gentil. Um portfólio em construção é normal.
- Não prometa vaga. Mostre o que deixa o portfólio mais forte.
